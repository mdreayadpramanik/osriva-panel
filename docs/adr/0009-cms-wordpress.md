# ADR-0009: CMS adapters, WordPress first

Status: accepted (Phase 6a, 2026-11-03)

## Context

Phase 6 adds a CMS catalog with adapters, starting with WordPress through WP-CLI. The
platform must not ship modified CMS code, must verify what it installs, and must not
keep administrator secrets.

## Decision

* **Packaging:** official Docker images, pinned:
  * `wordpress:6.6-php8.3-apache` (only the initial install);
  * `mariadb:11.4`;
  * `wordpress:cli-2.11-php8.3`.
* **Per instance:**
  * a private bridge network;
  * two named volumes (database, `/var/www/html`);
  * a MariaDB container without published ports and with a health check;
  * a WordPress container published on `127.0.0.1:<port>` only.

  Containers run with `no-new-privileges` and are restarted unless stopped. Every object
  is labelled `dev.osriva.cms=<name>`. Install refuses to reuse any existing object.
  Remove refuses to touch objects that are not labelled, and checks everything before
  deleting anything.
* **Secrets:**
  * the database password is generated on the server and never leaves it;
  * the WordPress admin password is generated by the panel, returned to the user once,
    sent to the agent, and redacted from the stored task parameters when the task ends
    (any parameter named `*password*` is redacted in listings and the audit log);
  * user-supplied values (title, URL, user, e-mail, password) reach WP-CLI as
    environment variables of a fixed script, so the shell never parses them.
* **WP-CLI runs in short-lived containers** that share the instance's volume and network,
  as `www-data` (33:33), and are removed afterwards. Read operations use
  `--skip-plugins --skip-themes`, so listing never executes plugin code.
* **Operations:**
  * `cms.wp.info` (servers.read): state, core version and available update, plugins,
    themes;
  * `cms.wp.verify` (servers.read): `wp core verify-checksums` and
    `wp plugin verify-checksums --all` against wordpress.org, which covers the
    "verified downloads" requirement for the installed files;
  * `cms.wp.update` for core, plugins or themes (servers.operate + re-auth);
  * `cms.remove`: keep or delete data. Deleting data needs re-auth plus typing the name
    in the dashboard.
* **Domains:** an optional domain creates a Phase 5 website that points at the instance.
  `WORDPRESS_CONFIG_EXTRA` honours `X-Forwarded-Proto` from the proxy, so WordPress
  knows it is served over HTTPS.

## Not done (Phase 6b and later)

* Staging, clone and migration (`wp search-replace`); changing the site URL.
* Backups and restores (Phase 7).
* Other CMSes (Joomla, Drupal, Ghost …).
* Image upgrades of the PHP runtime.
* Multisite.
* Admin password reset from the panel.
