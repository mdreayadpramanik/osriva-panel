# OSRIVA Panel — Database schema design

PostgreSQL 16+. All primary keys are UUIDs generated by the application, except
append-only logs, which use `bigint` identities. Timestamps are `timestamptz`.
Every tenant-owned row carries `organization_id`, and every query is scoped by it.

**Status legend:** ✅ exists (migration named) · 🗓 planned (phase)

**Never created, by design:** payments, invoices, subscriptions, prices, plans
with prices, ledgers, transactions, carts, orders-with-money. External billing
systems keep those. OSRIVA stores only an opaque `external_reference` text
when a provisioning request supplies one.

## Identity & access — ✅ `0001_core_identity.sql`

| Table | Key columns | Notes |
|-------|-------------|-------|
| `organizations` | id, slug (unique), name, kind (`operator`\|`customer`) | Default operator org is seeded. Customer orgs arrive in Phase 12. |
| `users` | id, organization_id → organizations, email (unique, case-insensitive), display_name, password_hash (Argon2id PHC), status, totp_secret_enc (AES-GCM), totp_enabled, totp_last_step, password_changed_at, last_login_at | |
| `permissions` | key (pk), description | Synced from code at startup. |
| `roles` | id, organization_id (NULL = built-in), key, name, description, built_in | Unique (org, key), plus a partial unique index on key for built-ins. |
| `role_permissions` | role_id → roles, permission_key → permissions | PK on both columns. |
| `user_roles` | user_id → users, role_id → roles, granted_by → users, granted_at | |
| `sessions` | id, user_id → users, token_hash (unique, SHA-256), expires_at, last_seen_at, reauthenticated_at, revoked_at, ip (inet), user_agent | Partial index on active sessions per user. |
| `audit_logs` | id (identity), organization_id, actor_user_id, actor_label, action, target_type, target_id, outcome, ip, user_agent, request_id, metadata jsonb, created_at | Append-only. Retention policy job planned (Phase 8). |
| `settings` | key (pk), value jsonb, updated_by, updated_at | e.g. `panel.mode`. |

## Servers, agents, compatibility — ✅ `0002_servers_agents.sql`

Implemented as: `agent_ca` (single row, encrypted key), `servers` (status pending/active/revoked, enrolment token hash + expiry, denormalised facts, last seen), `agent_certificates` (serial, fingerprint, expiry, revocation), `server_inventory` (latest snapshot + computed capabilities as jsonb). Planned for later phases: `server_groups`, `agent_tasks`.

| Table | Key columns |
|-------|-------------|
| `server_groups` | id, organization_id, name |
| `servers` | id, organization_id, group_id, name, hostname, status, last_seen_at |
| `agents` | id, server_id (unique), version, cert_fingerprint, cert_expires_at, enrolled_at, revoked_at |
| `agent_enrollment_tokens` | id, organization_id, token_hash, expires_at, used_at |
| `operating_systems` | id, server_id, family, distribution, version, kernel, arch, package_manager, init_system |
| `server_capabilities` | server_id, capability_key, status (enum of 6 statuses), reason, detected_at |
| `agent_tasks` | id, server_id, type, params jsonb, status, requested_by, exit_code, output_ref, created_at, finished_at |

## Monitoring & alerts — 🗓 Phases 3 and 8

`metric_samples` (server_id, ts, cpu, mem, disk, net — time-partitioned),
`alert_rules`, `alerts`, `notification_channels`, `notification_deliveries`.

## Applications & runtimes — 🗓 Phase 4

`applications`, `deployments` (with build log ref, commit, status),
`runtime_configs`, `app_env_vars` (values encrypted), `app_volumes`, `git_sources`.

## Websites, domains, SSL, DNS — 🗓 Phase 5

`domains`, `websites`, `proxy_routes`, `redirects`, `ssl_certificates`
(issuer, not_after, status, private key encrypted), `dns_providers`, `dns_records`.

## CMS — 🗓 Phase 6

`cms_catalog` (adapter key, supported versions), `cms_installations`,
`cms_versions`, `cms_backups`, `cms_migrations`, `cms_staging_links`.

## Databases, storage, backups — 🗓 Phase 7

`managed_databases`, `database_users`, `storage_volumes`, `backup_targets`,
`backup_policies`, `backups` (checksum, verified_at, encryption_key_id), `restores`.

## Plugins & integrations — 🗓 Phase 13

`plugins` (manifest, version, signature, enabled), `integrations` (config encrypted).

## Hosting Provider Mode — 🗓 Phases 10–11

`data_centers`, `sites`, `racks`, `nodes`, `resource_pools`, `networks`,
`vlans`, `ip_pools`, `ip_addresses`, `virtualization_providers`,
`vps_instances`, `technical_templates` (CPU/RAM/disk/bandwidth quotas. **No
price columns**), `hosting_services`, `hosting_accounts`, `allocations`,
`provisioning_tasks`.

## Customers & API — 🗓 Phases 11–12

`customers` (maps to a customer `organizations` row), `customer_services`,
`api_credentials` (scoped, key hash, rotation), `webhook_endpoints` (signing
secret encrypted), `webhook_deliveries`, `idempotency_keys`.
